# Product Boundary

DexRecover owns one vertical slice: **runtime DEX recovery quality**.

## In

- dumped DEX/CDEX identity and validation
- duplicate removal
- runtime capture timelines
- before/after DEX deltas
- method-body/package/runtime-class recovery metrics
- clsdumper integration
- narrow guidance for another DEX capture

## Out

- native decompilation
- vulnerability scanning
- API exploitation
- traffic interception suites
- generic device automation
- full Android reverse-engineering orchestration

An out-of-scope result is still useful. For example, "the recovered managed layer is thin and the feature is native-heavy" is a successful DexRecover conclusion because it tells the analyst to stop spending time on DEX recovery.
